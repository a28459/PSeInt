01 · De la tarea al merge

El flujo que repetiremos.

El código importa, pero en un equipo profesional importa también cómo llega un cambio, cómo se trabaja sin romper lo existente y cómo termina integrado de forma controlada.

01

Issue / tarea

Traducimos una petición a una tarea clara, con objetivo y criterios de aceptación.

GitHub Issues
02

Rama feature

Creamos una rama para desarrollar el cambio sin tocar directamente la rama principal.

03

Commit & push

Guardamos cambios con sentido, revisamos el histórico y los publicamos en remoto.

SourceTree
04

Pull Request

Otro miembro revisa el diff, comenta, aprueba y finalmente se integra el cambio.

Review + Merge
05

Integración continua

Tras el merge, una acción automática valida que el proyecto está preparado para desplegar.

CI · GitHub Actions
06

02 · CI/CD

De un merge a una web online.

La automatización reduce pasos manuales: cada cambio aprobado sigue siempre el mismo proceso, queda registrado y puede fallar de forma visible antes de llegar al usuario.
